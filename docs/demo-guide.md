# 五分钟演示：工单 Agent 与人工审核

推荐现场使用明确标记的零付费演示，再展示真实评测证据。演示替身保证流程可重复，不用于宣称真实模型效果；模型实测记录见[RAG 评估](rag-evaluation.md)。

## 启动

在仓库根目录配置 `.env` 的 PostgreSQL，数据库用户需有创建测试 schema 的权限。模型凭据和 Milvus 均非演示必需。

```powershell
uv sync --locked
uv run --no-sync python scripts/start_local.py --demo --check
uv run --no-sync python scripts/start_local.py --demo
```

打开工作台 `http://127.0.0.1:8501`。终端输出本次 `data/cache/m5/demo-tm_test_<UUID>.json` 的路径，从该文件复制 reviewer_token 登录，不在截图、演示录屏或提交中展示凭据。演示 API 在 8010。正常 Ctrl+C 停止并清理本次隔离数据。

端口占用时使用 `--api-port 8011 --ui-port 8502`。`--check` 只验证数据库连通和端口可绑定，不表示真实 Milvus/模型可用。

## 操作顺序

涉及写入的操作先生成待确认请求，再点击“确认提交 / 原样重试”执行；页面预览请求或生成模型提案都不等于已经发布。

| 时间 | 操作 | 应观察到什么 |
|---|---|---|
| 0:00—0:30 | 展示页面合成演示标记，介绍工单→提案→人工审核 | 模型不能自动发布或关单 |
| 0:30—1:40 | 新建标题“正常建议”、正文“本机代理连接失败”；处理最新消息，确认运行；在运行与审核查看提案，再编辑后批准，最终动作选解决建议 | 审核前 waiting_review；批准后新增内部回复，工单仍 open |
| 1:40—2:20 | 人工确认解决并关闭；填写知识文章的问题、适用条件、步骤、验证结果，经确认批准入库 | resolved；知识进入演示替身索引，页面注明不能算真实 Milvus 验证 |
| 2:20—3:25 | 新建标题“补问继续”，批准追问；录入客户补充“已启用本机 HTTP 代理”，再次处理并审核建议 | awaiting_customer→客户更新→新运行；两个运行与有序消息保留 |
| 3:25—4:00 | 新建标题“转人工”，处理并批准转人工 | 工单 escalated，自动处理入口受状态限制；人工仍可接管后续 |
| 4:00—4:25 | 新建标题“故障演示”，发起处理 | failed、稳定错误提示，客户原文保留；HTTP 请求成功接收不等于 Agent 运行成功 |
| 4:25—5:00 | 展示评估说明与本轮验收记录 | 清楚区分模型效果、真实数据库集成、替身演示及未覆盖分支 |

标题是替身的公开路由规则：含“故障”→失败，含“转人工”→转人工，含“补问”且未批准过追问→追问，其他→解决建议。这些规则只存在于 `DemoRunner`，正式运行不按标题硬编码。

## 真实模式的使用边界

已有冻结知识和本机 PG/Milvus 时使用 `start_v2_flash.cmd --skip-infra`；工作台 8501、API 8000。Decision 为 qwen3.8-flash，Judge 读取 `.env` 的 deepseek-v4.1-flash 配置，处理会产生真实费用。本次收尾没有授权额外真实调用。

新知识发布到 production-v1；日常 v2 启动入口仍检索 synthetic-v2，不会自动看到新发布文章。要演示真实“发布后可检索”，需明确选择 production-v1 的服务配置与已经就绪的索引。已有[真实验收记录](rag-evaluation.md#最新代码的真实路径证据)使用独立测试集合完成，不在现场临时重建共享索引。

演示出现问题时：先确认页面是否仍是演示模式、当前角色和工单状态；查看运行错误与历史记录。未修复时展示保存的证据，明确说是历史实测，不把录像或替身当作本次现场模型执行。
