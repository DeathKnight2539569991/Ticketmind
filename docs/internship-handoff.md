## 环境与日常使用

从仓库根目录执行，需 Python 3.12、uv 和 PostgreSQL：

```powershell
uv sync --locked
if (-not (Test-Path .env)) { Copy-Item env.example .env }
# 编辑 .env 的 PostgreSQL 连接；保留已有配置和凭据。
uv run --no-sync python scripts/start_local.py --demo --check
uv run --no-sync python scripts/start_local.py --demo
```

工作台 `http://127.0.0.1:8501`；演示 API `http://127.0.0.1:8010`。终端只输出临时凭据文件路径，从文件取 reviewer_token 登录，不将凭据放入截图。模型、检索和知识索引是有明确页面标记的替身；工单、审核、消息、迁移和检查点使用真实隔离 PostgreSQL。正常 Ctrl+C 清理本次 schema 和临时凭据，不删除其他数据。

已有真实知识库的日常模式使用 `start_v2_flash.cmd --skip-infra`，模型为百炼 qwen3.8-flash Decision 与 `.env` 指定的 deepseek-v4.1-flash Judge，检索 BM25。真实“处理”会产生费用，不属于零付费演示。新 `.env` 示例已与该组合一致；旧 `.env` 不自动覆盖。生产默认知识库与 frozen synthetic-v2 不同，切换知识库须重启对应 API 配置。

新机器没有真实索引时先使用隔离演示。正式知识初始化参见[知识配置](knowledge-writeback.md#初始化与运维命令)：迁移→seed→已有向量缓存导入（可选）→显式索引同步。BM25 可在没有文档向量时就绪；Dense 需要独立向量状态。同步是写操作，应先核对目标数据集；缺缓存时不得通过付费参数隐式补调。

## 已知边界

- 保留人工审核；模型仍可能追问不完整、引用不适用或作不当承诺。Judge 放行不是正确性证明。
- 最新真实运行尚未覆盖主动二次检索、详情读取、Judge 拒绝修正；工程分支由确定性测试验证，不能混称真实模型覆盖。
- 037 双轮真实测试使用过同批首轮结果恢复，不是一次连续执行，也不是产品恢复接口的端到端验收。
- 知识库仅 12 篇合成历史文档，无真实客户收益、线上并发能力或检索规模指标。
- 没有邮件外发、真实派单、多租户和生产运维验收；页面“发布”是内部工单消息落库。
- 进程被硬杀时可能遗留临时 schema；只按当次记录核对清理，不批量删除所有 `tm_test_` 数据。

这些边界不阻止本地实习演示。后续优先处理实际演示故障与明确业务错误；新增功能、线上部署和付费实验另行确定范围。
