## 已实现的使用流程

1. 使用服务端预置身份登录，按状态和页码查看工单，或创建工单。
2. 查看原始客户消息，处理最新客户信息；返回 failed 时直接展示失败原因，不把 201 当成功。
3. 查看运行历史、理解、草稿、引用、版本化来源、工具轨迹与 usage。
4. reviewer 批准、编辑后批准或改为转人工；保存原草稿、审核记录与实际发布消息。operator 无审核/人工回复/关闭入口，后端再次校验权限。
5. 客户补充会使旧方案失效；重新处理后形成新运行。人工回复和确认解决各有独立入口，关闭需要明确确认和说明。

文档入口：[演示与启动](m5-demo.md)、[架构/API](architecture.md)、[来源与贡献](sources-and-contributions.md)。

## 关键实现

- `workbench/app.py` 只使用 HTTP API，不绕过业务层直写数据库。UI 凭据仅存会话，退出清空，不共享缓存。
- 读取快照与待确认请求分离。每次写入固定 payload、expected_version 与 Idempotency-Key；超时后原样重试，409 后核对最新记录。
- 审核应用失败时原记录提供原 key，原审核人可以恢复同一审核；不会新建另一份审核、重算模型或覆盖草稿。
- `start_local.py` 管理 API/UI 生命周期，数据库和 Milvus 保留；`serve_m5_demo.py` 只在自己创建的随机 schema 中运行替身演示，清理范围由 `isolated_database` 限定。
- 新增 Streamlit 1.64.0 与依赖，HTTPX列为运行依赖；没有新增数据库迁移、改检索策略或模型提示词。

## 保留的限制

- 模型/向量新调用 **0**。全部新工作台三路径验证使用替身，不代表新的真实模型三路径验收。M4 5/6动作匹配、3条虚称已转交、33条Agent未执行的限制不变。
- Docker在本轮开始时未运行；可选PostgreSQL容器和新机器完整模型/Milvus初始化未端到端实测。向量缓存不提交，新机器使用真实检索需配置服务并另行授权初始化向量。
- 提供约4分钟演示脚本，未制作录像成片。初始基线的逐文件上游来源证据不足，来源说明保留这个边界。
- 仍为单实例单worker、单团队预置身份，无外部消息系统。刷新浏览器会失去会话中未保存的请求；先查记录，已保存审核可取原key恢复。
- 本轮实现交付不意味着M0—M5所有“真实模型/新环境/独立test/录像”验收项均已完成。
