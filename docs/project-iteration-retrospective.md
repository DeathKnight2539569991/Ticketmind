### V0｜2026-09 上旬—09-13：我手动把独立能力接起来

**问题 / 现象：** 最初的工单创建、理解工单与 Dense 检索是独立能力。图只有 `START → understand → END`，还不能把检索证据带入同一流程。

**我做了什么测试：** 学习阶段采用解释后手动写入的方式，历史记录确认我运行过理解图和 CSV 检索，并确认分隔符案例 `SYN-HIST-V2-002` 排第一。我要求后续复用真实查询缓存，不重复调用模型。

**测试发现了什么：** `search_param` 应为 SDK 正式参数 `search_params`。以前能返回案例，也不能证明指定参数生效。接图时新导入写入后，旧的 LangGraph 和理解函数导入被删掉，需要补回。

**如何定位 root cause：** 对照 SDK 实际参数和源码。参数拼写、缺导入是代码问题；检索是否相关、案例是否适用是其他问题。先把导入、调用和状态更新弄正确，再判断真实效果。

**我手动做了什么调整：**

- 改 `search_params`，补检索返回类型；我回复“完成”后源码核对确认已写入。
- 增加 `retrieval_query / retrieval_hits / RetrievalUpdate`，按讲解手动写检索函数。
- 补回 `START / END / StateGraph / CompiledStateGraph / understand_ticket` 等需要的导入。
- 将图接为 `START → understand → retrieve → END`，检索节点返回状态增量。
- 确认用原始“标题＋正文”构造查询，不直接使用模型摘要。

**为什么这么改：** 我当时在理解节点、state、客户端与返回值的关系。检索只交回证据，不因为命中就直接决定工单已解决；记录实际 query，后续才能检查搜了什么。

**调整后结果：** 参数、状态、检索函数与接图代码均有核对记录。修改参数后的完整新排名输出没有记录，不补写分数；也没有实验能说明原文查询一定优于摘要。

### V1｜2026-09-13—09-14：我要求真实链路、精确复用，进入处理和审核阶段

**问题 / 现象：** 新查询包含标题与正文，旧 CSV 向量不能直接复用。若整张图结束才保存，后续检索失败可能让前面成功结果丢失。

**我做了什么测试：** 我明确提出“直接走真实流程不要模拟”，批准一次理解、一次 Embedding，并要求保存复用。正式请求前先核对代码与 Milvus。后期 M0/M1/M2 的工程测试委托执行，我核对结果，不把替身与缓存回放叫全新模型链路。

**测试发现了什么：** 缓存语义需要清楚：理解结果与查询向量能精确复用，检索仍可查真实 Milvus。输入格式变化不能硬用旧向量。M1 的真实草稿还夹带未经环境确认的停用代理建议。

**如何定位 root cause：** 我先澄清缓存了什么，再要求区分流程落库与模型内容质量。输入变化是缓存身份问题；操作型追问是模型边界问题。

**我提出的调整：** 成功立即保存、核对输入/模型/配置、检索只返回证据；随后按阶段计划推进三类待审提案与审核、客户补充。具体业务实现委托完成，不写成我手写全部后端。

**为什么这么改：** 能接着验证失败，不每次从头付费；同时让模型建议先可审核，不能直接发布或关闭工单。

**调整后结果：** M1 记录 58 项通过，真实单例复用理解/向量，只新增一次 Decision；M2 记录 96 项和 4 个进程中断场景。内容仍需审核，测试数量不表示模型可靠。

**HITL 的准确时间：** M1 建立 waiting_review 边界，M2 才实现审核 API、持久化 interrupt/resume、客户补充和审核应用。我确认过三条合成提案的审核演示，并批准 GLM 建议的具体编辑稿；没有把它说成真实客户解决确认。

### V2｜2026-09-14—09-15：我追问“为什么卡住”，从反复验收转向同条件模型对照

**问题 / 现象：** 固定超时补充场景反复失败。客户已说明无代理、只读全年查询、2秒等待超时、10秒等待约4秒返回，模型仍错用代理案例，或不给合法搜索动作。

**我做了什么测试：** 我批准固定场景复验，随后明确要求换 `qwen3.8-27b`、`qwen3.8-max-0902`、`glm-5.2`。对照保持输入、prompt和检索条件一致，只变 Decision。

**测试发现了什么：**

- Flash 错用007的代理条件，外推5—10秒；后来把操作包装成追问。
- 加强动作边界后，Flash有搜索意图却漏next_step。
- 27B搜索意图合适，但返回数组，协议要求对象。
- Max格式合法、能排除候选，却提前转人工，未先重检索。
- GLM-5.2返回合法搜索，真实新向量找到006，继续给出建议。

**如何定位 root cause：** 我明确问过：

> “我们卡了这么久的验收究竟在纠结什么，是模型问题还是代码问题？”

我还问是不是模型能力导致“输出总是少东西”。原始响应和工具轨迹支持区分schema遵守、证据使用、工具选择与措辞，而不是全部算代码失败。

**我提出的调整：**

> “如果是模型问题，下次你直接调用glm-5.2，否则还是使用原来的flash进行测试。”

随后我直接指定GLM，批准最终编辑稿。中间每次加入引用原文、操作词或动作规则的实现由委托调试产生，不冒称都由我逐条手改。

**为什么这么改：** 我不想反复用同一个模型的行为失败证明代码。先判断失败所属层，再改变模型变量，避免一直机械重试。

**调整后结果：** GLM完成合法重搜索、真实Embedding/Milvus、006建议与待审；我批准编辑后应用，工单仍open。原稿有过度断言，所以成功链路不等于无需审核。

**实验边界：** 首检实际返回与模型可见候选分开保存，006是受控过滤，不是删索引。这不是自然召回评测，也不是总体模型排名。

### V3｜2026-09-15：我推进三模式和质量评测，不只满足一个样本成功

**问题 / 现象：** Dense单样本能用，但缺关键词对照和真实Agent质量判断。

**我做了什么测试：** 我明确提出M3实现BM25、Dense/BM25/Hybrid及RRF，接工单并做真实对比与失败路径。样本少时我要求补诊断样本；后续推进M4，记录为51查询、153组三模式真实检索，以及首批6条Agent。

**测试发现了什么：** E_TIMEOUT查询的BM25首位是不同错误码008，超时线索排3/4；Hybrid将007排第一但未消除干扰。无答案政策仍返回候选。扩大实验三模式指标都高，Agent仍虚称转交、漏问。

**如何定位 root cause：** 排名、分词与正文说明完整词项不等于条件成立。检索命中与模型回答要分开。具体词典和RRF实现由委托开发完成，不写成我的自研算法。

**我提出的调整：** 从单例走向同条件三模式评测及Agent质量评测，补样本、保留失败和来源，再针对暴露的输出问题改约束。

**为什么这么改：** 我想判断新增检索方式有没有实际价值，并识别失败属于召回、证据使用或知识覆盖。

**调整后结果：** 12篇语料、51查询、有相关来源分母29，三模式Hit@5/Recall@5/MRR@5均1，不证明Hybrid更好。6条Agent动作5/6，但006/015/018虚称转交，必要问题组完整覆盖0/4，不等于没有有效追问。

### V4｜2026-09-17：我明确“待审提案不能声称已经执行”，再要求冻结完整评测

**问题 / 现象：** 草稿写“已转交”“已经通知”“稍后工作人员联系”，系统却没有外部派单通知能力，只生成待审提案。

**我做了什么测试：** 我要求先读M4失败证据再改，随后冻结配置完成剩余33条。评分区分动作、风险、追问、证据、无答案和工程失败，原6条不能覆盖。

**测试发现了什么：** raw动作22/30、系统最终动作19/33；8条失败，4条操作规则误伤。必要问题组2/23。该批原稿虚称已完成为0，但仍漏了2条未来承诺，如“届时会由人工确认”。

**如何定位 root cause：** 我在需求里明确这是系统能力与回复声明不一致，不是禁止未来时。允许建议人工，不能声称人工已接手；冻结结果又说明词表无法稳定区分否定、过去经历与承诺。

**我提出的调整：**

- 不只改prompt，在提案validation加确定性保护。
- 不简单禁止人工/联系/转交，合法建议保留。
- 违规明确失败，不偷偷改写草稿。
- 不改retrieval、不加reranker、不覆盖历史结果。
- 正式评测启动后，不因失败边改prompt/标签/数据边刷分。

**为什么这么改：** 我要真实的能力边界与可信质量基线，不是让测试表面全部通过。

**调整后结果：** 规则落地，但正式评测仍有误伤和漏检，推动我下一步提出Judge。没有把“已完成虚称为0”包装成所有状态与承诺问题都解决。

### V5｜2026-09-18：我提出独立Judge，并具体精简其事实来源与prompt

**问题 / 现象：** 操作词规则分不清“以前停用过吗”“请现在停用”“不要修改”，未来承诺也有漏检。

**我做了什么测试：** 我要求真实模型复验之前的追问不足、误伤和承诺样本；先指定GLM-5.2/Flash，再要求GLM-5.3/DeepSeek并真实测试。

**测试发现了什么：** Flash Judge仍误判历史询问或“建议人工核查”；DeepSeek最小正反例5/5，036一次修正后通过，复杂016/020/034仍错，005有协议错误。GLM-5.3部分请求超时或截断，新追问完整性没有完整可评估输出。

**如何定位 root cause：** 我明确词表不应承担语义，又指出understanding是模型派生信息，不能证明客户提供过事实，否则上游错误同时影响Decision与Judge。

**我提出的调整：**

1. 独立Judge、不同模型、四类职责，暂不解决追问完整性。
2. 保留schema、证据身份和工具等确定性校验，不全交给LLM。
3. 拒绝后反馈违规原文与理由，只修正一次，再失败安全退出。
4. 删除Judge输入understanding，客户原文作为事实来源。
5. 精简工具字段，去error/result_summary，完整审计不删。
6. capabilities只写真实系统能力，判定规则放prompt。
7. 删除大量固定句子exact examples和重复schema说明，保留抽象语义及违规原文真实性。

**为什么这么改：** 我希望事实来源和职责清楚，减少对固定句子堆规则。加模型、加prompt长度不等于更可靠。

**调整后结果：** Judge精简相关74项工程测试通过，其中8项真实HTTP/PG、模型替身。真实诊断只是部分改善，没有精简prompt后的总体A/B成绩；追问完整性仍不足。

GLM-5.3调用兼容修补属于实现过程，不写成我亲自查清并优化模型推理机制的故事。

### V6｜2026-09-19—09-20：我控制40题对照变量，要求失败日志，并质疑空引用约束

**问题 / 现象：** 单例换模型不能比较整体质量，而且项目已改输入和护栏，需要以实际代码评测。

**我做了什么测试：** 我提供40条合成工单，要求同输入、知识、prompt、工具、Judge，仅改Decision；明确模型ID为qwen3.8-max-0902和qwen3.8-flash。我纠正配置：统一bm25/top_k=3，不用默认Dense，不混Hybrid。

**测试发现了什么：** Max业务成功28/40，Flash29/40；待审完成34/40、37/40。Max5个、Flash3个schema失败与非空evidence_ids要求有关。037客户已确认owner尾随空格，模型建议合理且不强引分隔符案例，却被空引用拒绝。

**如何定位 root cause：** 我事先要求“运行失败案例要有详细日志，我稍后要查看为什么失败”，明确schema合法/Judge通过/程序强制转人工不能等于业务成功。结果后追问：

> “如果evidence_ids允许为空，max和flash还有几次失败？”

这是检查过严协议的影响，不只是认为更大模型更好。

**我提出的调整：** 控制变量，保留每题原文、证据、工具、错误与用量；争议单列，检查空引用规则的反事实。项目随后允许客户事实充分时无历史引用，非空引用仍需真实。

**为什么这么改：** 不应为了格式强套根因不同的历史案例，也不能把放宽后“可能通过”直接回填成旧成绩。

**调整后结果：** 原结果保留，后来无引用路径有真实待审证据，但没有重跑80次形成新整体成功率。两模型差一题，不宣布显著优劣。

**归属边界：** 空引用审查是我的明确问题；后续schema具体改动的逐项指示/手改归属记忆不确定，不写“我手改Pydantic最少引用数”。

### V7｜2026-09-18—09-22：我把审查重点收回数据结构与核心业务，明确无向量BM25需求

**问题 / 现象：** 模块增加，我担心数据冗余与事实不一致。后来发现BM25查询不用向量，但新知识发布仍依赖文档向量。

**我做了什么测试 / 审查：** 我发起结构审查，并纠正“完整调用链没有问题，重点检查数据结构设计”。下一次要求先只看核心代码，不自行测试写代码，先了解问题再决定处理。

**审查发现了什么：** 报告发现questions与实际reply/人工编辑历史不一致、混合角色正文、两套证据输出；核心审查还指出审核改文字不改动作、失败无独立接管、整段会话写知识和发布依赖向量。探针和具体发现由审查产出，不冒称我全部亲自构造。

**如何定位 root cause：** 我要求检查字段职责、重复存储和模块契约，不再从头验证调用链，又明确只看项目核心代码而不是阶段脚本。

**我提出的调整：**

> “可以支持无向量的bm25，但是要兼容hybrid检索，便于我随时切换。”

其他审核、恢复、知识文章等具体修改是在授权处理后完成，是项目结果，不全部归为我的逐项设计。结构化输入和删除理解节点同样不能仅凭项目发生就说是我手改。

**为什么这么改：** 我希望关键词模式真正独立可用，并保留Hybrid切换；不能查询时不依赖Embedding，发布时却被它阻塞。

**调整后结果：** BM25/Dense独立就绪，无文档向量也能发布并参与关键词检索，Hybrid可用BM25来源；工程及真实知识路径验证。缺向量并不代表Dense可用，实际服务故障仍须明确失败。

### V8｜2026-09-24—09-28：我追问最新真实loop覆盖，不把测试数量当完整验收

**问题 / 现象：** 修复后报告286项和4条真实集成，我关心改过loop后是否真的完整真实验证。

**我做了什么测试：** 我问“所有改动有没有涉及Agent loop，改完有没有完整真实测试”，提醒已有40题，再要求复用旧题，每个缺失路径挑例，考虑成本速度，测试前确认配置。

**测试发现了什么：** 最新4例均一次Decision/Judge直接待审，只有首检；新4例5次运行后，审核关闭知识与实时Hybrid直接通过，追问续接恢复后完成，再检索/详情/修正三个分支仍未触发。

**如何定位 root cause：** 我的审查点是历史模型质量、最新工程回归、最新真实轨迹不能互相代替。选了一条case也不代表模型实际用了目标工具。

**我提出的调整：** 不从头重复所有题，小批量复用旧样本补覆盖；明确配置、预算与实际路径。具体筛题和执行委托完成。

**为什么这么改：** 有限成本回答关键不确定项，不把未触发分支说成通过。

**调整后结果：** Decision5、Judge5、查询Embedding1，共报告26,505tokens；三分支未覆盖。9月28日286项工程通过、模型替身，不增加模型质量成绩。当前适合本地演示，不是模型全路径可靠保证。

## 二、最值得面试讲的五次个人迭代

### 1. 从反复验收转向判断模型还是代码问题

> **问题：** 固定超时case反复错用证据、漏字段或不搜索。
>
> **测试：** 我批准同场景复验，再指定27B、Max、GLM同条件对照。
>
> **定位：** 我追问到底卡的是代码还是模型，要求区分协议、工具选择和证据使用，原文与轨迹支持这样拆分。
>
> **修改：** 我明确模型行为验收用GLM-5.2，代码集成仍可用原Flash，避免机械重试。
>
> **结果：** GLM受控重检索成功，原稿仍需编辑。我不把单例成功当全局模型排名。

### 2. “已转交”没发生：我定义能力与声明不一致

> **问题：** 草稿写已通知/转交，系统只有待审。
>
> **测试：** 我要求依据失败记录修规则，再冻结33条完整评测，不刷分。
>
> **定位：** 这不是禁止未来时，而是不能把未执行动作说已完成、不能承诺不存在的能力。
>
> **修改：** 我要求prompt加确定性guardrail，允许人工建议，违规不偷偷改写。
>
> **结果：** 冻结评测仍有未来承诺漏检和正则误伤，所以我继续提出Judge，没有宣称首次修改完全解决。

### 3. 我精简Judge的事实来源和prompt

> **问题：** 规则误伤，Judge长语境仍错，输入又有派生摘要与重复规则。
>
> **测试：** 我要求真实复验旧case，并指定新Decision/Judge组合。
>
> **定位：** 我指出understanding不是客户原文，不能作为已知事实，还会让两个模型共享上游错误。
>
> **修改：** 我要求删understanding、精简工具、能力事实与规则分开、删除大量exact examples及schema重复，保留窄职责和一次修正。
>
> **结果：** 相关工程通过，但没有新整体语义A/B。prompt变短不能直接说质量提高。

### 4. 我控制40题对照，并质疑强制引用

> **问题：** 失败混着模型理解、协议和程序强制动作。
>
> **测试：** 我提供40题，固定BM25/top_k=3、同prompt/知识/Judge，仅换Decision，要求详细日志。
>
> **定位：** 合理建议因空evidence_ids失败，我追问允许空引用后还有多少失败，检查合约影响。
>
> **修改：** 我要求业务成功与运行完成分别报告，保留争议与旧原文，不回填成绩。
>
> **结果：** Max28/40、Flash29/40，差一题不说明显著优劣；后续新协议没有变成旧评测的新准确率。

### 5. 我要求无向量BM25可用并兼容Hybrid

> **问题：** BM25查询不需向量，知识发布却依赖它。
>
> **测试：** 我先要求核心审查，再确认业务需求，实现后隔离回归和真实知识路径验证。
>
> **定位：** 文本与向量就绪被绑在一起，阻塞不需要向量的能力。
>
> **修改：** 我明确无向量BM25可发布，还能随时切Hybrid。
>
> **结果：** 两路独立就绪，知识可先走关键词；不假装缺向量时Dense也可用。

## 三、五个Failure Case

### Failure 1｜超时问题错用代理案例

- **输入：** 客户无代理、2秒等待、约4秒完成，只读全年查询；受控首检不给正确006。
- **错误：** Flash错用007代理条件、外推5—10秒，后续还漏next_step。
- **Root cause：** 证据适用、协议和工具选择分别失败。
- **我的介入：** 追问模型还是代码，明确要求27B/Max/GLM同条件对照。
- **我的调整：** GLM用于模型行为验收，工程验证独立；批准具体编辑稿。
- **结果：** GLM合法搜索006建议，仍需审核，不是总体模型优劣结论。

### Failure 2｜虚称已转交、保证未来人工行动

- **输入：** M4“已转交团队”，034/036“人工之后会确认”。
- **错误：** 只是待审，无外部执行或安排依据。
- **Root cause：** 模型把建议写成执行事实，词表漏语义变体。
- **我的介入：** 明确区分未发生动作、合法建议、无依据承诺。
- **我的调整：** 先要求prompt＋确定性约束，再要求独立Judge和一次修正。
- **结果：** 部分拦截修正成功，复杂表达仍误判/漏检。

### Failure 3｜否定和历史询问被当成新操作

- **输入：** 005“不要修改”、016“之前是否停用过”，对照“请现在停用”。
- **错误：** 正则误伤；Flash Judge长语境也误判。
- **Root cause：** 否定、时态是语义问题；部分原稿另有重复事实，不应整稿无条件放行。
- **我的介入：** Judge需求明确历史询问允许、新操作拒绝，并要求真实复验。
- **我的调整：** 保留确定性代码，四类语义Judge，后续删固定句堆积和派生事实。
- **结果：** DeepSeek短句5/5，复杂016等仍错，不能称彻底修复。

### Failure 4｜事实足够，空引用导致合理建议失败

- **输入：** 037确认owner尾随空格、模板精确匹配，未正式导入。
- **错误：** 模型不给不适用来源，evidence_ids为空，被最少一条引用拒绝。
- **Root cause：** 合理依据被等同为必须有历史引用。
- **我的介入：** 追问允许空引用后两模型还剩多少失败。
- **我的调整：** 审查协议造成的失败，反事实与正式成绩分开；具体手改归属记忆不确定。
- **结果：** 后续允许无历史引用并有真实待审证据，旧80次成绩未重写。

### Failure 5｜真实集成“通过”，却没覆盖多步loop

- **场景：** 最新286工程测试与4例真实模型集成。
- **缺口：** 只有首检与直接Decision/Judge，不能证明再检索/详情/修正。
- **Root cause：** 工程、历史质量、当前自然轨迹口径混用。
- **我的介入：** 追问改动是否涉及loop、是否完整真测，提醒已有40题。
- **我的调整：** 复用旧题小批量逐路径补测，确认成本配置。
- **结果：** 两条直接通过、一条恢复后通过、三个分支未触发。覆盖不足不直接等于代码错误。

## 四、面试问答

### 1. 介绍一下这个Agent项目

> TicketMind处理合成SaaS支持工单，检索历史、受控选工具、生成解决/追问/转人工提案，人审才发布，客户补充后继续处理，解决后可整理知识。
>
> 我早期手动接通理解、Dense与图状态，后期审查模型行为、提出护栏和prompt调整、控制评测变量并追问最新真实覆盖。开发用AI辅助，我明确区分我的要求和委托实现。

### 2. 你做过哪些测试？

> 早期我手动运行理解图和CSV检索。后期我提出固定超时对照、三种检索、33条冻结、Judge真实诊断、40题双模型和最新loop补测，执行委托完成。
>
> 我强调同条件仅改一个变量、失败日志、业务成功与运行完成分开。项目最新历史工程回归286项、真实PG/Milvus、模型替身，测试代码并非全部我手写。

### 3. Agent出错时怎么定位？

> 我先要求分清代码和模型。超时case反复失败时，我问到底是协议、工具选择还是代码；40题时要求保留原文、证据和详细失败日志。
>
> 按输入、召回、实际工具、模型输出、schema/Judge、业务状态逐层看。空引用是协议，错用代理是证据使用，没选择工具是覆盖问题，不能总加prompt。

这是可解释的方法，不声称所有异常堆栈与探针都由我亲自构造。

### 4. 怎么验证prompt修改有效？

> 我要求固定样本配置、保留失败；正式33题不边失败边改prompt/标签，之后另建诊断。Judge要真实复验，不只靠替身。
>
> 超时case多次改prompt仍失败要保留；GLM单例不说明prompt普遍有效，精简Judge的工程通过也不等于语义准确率上升。

### 5. 为什么用Hybrid？

> 我推进三模式，因为症状是自然语言，错误码和字段又需词项匹配。项目RRF融合排名，不直接相加不同分数。
>
> 固定超时开发查询的首位有改善，但融合只得候选，条件适用要另判断，不能把相似度当正确概率。

具体RRF与分词实现委托完成，不说自研算法。

### 6. Hybrid真的更好？

> 不足以证明。早期开发排名有差异，但小样本、标签待审。51查询、12篇语料、有相关分母29，三模式指标均1，区分不了。
>
> 我在40题比较明确固定BM25，不引入Hybrid变量。以后需更大语料、独立标签、难负例，还看延迟和向量成本。

### 7. 为什么不完全用LangGraph？

> 结构逐步形成。早期我手动接理解和检索，M2外层图负责compute到review持久化恢复；内部两个只读工具由Python循环做边界。
>
> 内层两节点图没有逐工具检查点收益，可简化。没有全图化对照，也不能保证所有工具无重算恢复。

### 8. 为什么还有Python while loop？

> 两个工具用有界循环表达决策、校验、执行、更新和再决策直接。搜索最多两轮含首检，详情两个，步骤八个，Judge修正一次。
>
> 我关心实际有没有经历多步，而不是看到循环代码就认定覆盖。最新自然轨迹没触发的必须标未覆盖。

具体循环和预算代码不是我的全部手写成果。

### 9. 有observability吗？

> 有快照、证据、分路排名、工具、usage、Judge、审核与真实消息。我的明确要求是40题失败有详细日志，保留每题原文/证据/错误/用量方便查原因。
>
> 没有已验证的LangSmith/OpenTelemetry或告警；离线原文留存不代表生产所有非法Decision都有完整记录。

不把日志脱敏和资源清理修补写成我的个人发现。

### 10. 最大不足是什么？

> 语义质量，尤其追问完整性与证据适用性。我要求过真实检查追问不足，它并未被四类Judge附带解决。动作对、Judge通过不等于问全和原因对。
>
> 最新loop覆盖仍缺三分支，历史评测不能填新版本；还有小合成知识、本地单实例，无线上收益证据。

### 11. 为什么没有multi-agent/MCP？

> 首版单团队两个只读工具，困难在事实、证据、约束、人审，没有必要为了技术名称扩大。Judge只是检查组件。
>
> 我要求过开发子Agent补样本/选case，那不是产品multi-agent。没有multi-agent或MCP对照实验，不说试验后淘汰。

### 12. 重新做会怎么设计？

> 更早明确客户原文、证据、草稿和真实消息的权威来源；少派生摘要，Judge窄职责，避免语义词表。
>
> 评测从一开始分动作、追问、证据、运行和工程，保留原文配置；诊断和独立评测分开。BM25/Dense独立就绪，图与循环只留实际收益。

这是当前建议，不是过去已实现功能。

## 八、尝试过的方案与不足

**个人明确推进过：** 固定场景换模型、先确定性声明规则再Judge、精简Judge而非无限加例子、固定BM25模型对照、无向量BM25兼容Hybrid。

**未试过：** reranker、多Agent运行架构、MCP服务、完全图化性能对照，不说试验效果差才不用。

当前不足：

1. 追问完整性、证据适用性没有可靠保障，Judge不覆盖。
2. Judge复杂语境误判漏检、协议错误，最小正反例不等于真实可靠。
3. 最新再检索/详情/修正未自然触发；工程替身与历史不能代替。
4. 小语料、合成数据、委托标签，缺真实客服与独立人类评审。
5. 生产非法Decision原文审计不足，无已验证集中trace/告警。
6. 内层图与循环、首检全文与详情仍有冗余，没有逐工具无重算保证。
7. 单实例、无可靠队列/真实外发，无线上收益指标。
