# glm-5.3 + deepseek-v4.1-flash 真实诊断

**结论：部分改善，尚不能判验收通过。** DeepSeek 正确处理了全部 5 个最小正反例，原有两条未来人工承诺也均被拦截，036 完成一次修正后通过。但复杂历史询问、未知事实和流程前提仍有误判；005 出现 Judge 协议错误。新 Decision 的两份完整性样本没有产生可评估的完整回复，不能宣称追问不足已解决，也不能把超时/截断算作追问质量失败。

## 实验设置与实际用量

- 用户明确授权切换模型并付费重测；Decision `glm-5.3`，Judge `deepseek-v4.1-flash`。
- 仍为 7 份历史原稿、5 个最小正反例、005/026 新 Decision、016/034/036 单次修正。理解和检索上下文来自冻结记录，不重新调用理解、Embedding 或 Milvus。
- 与上一轮相比，前 12 个固定 Judge 请求的 **system_prompt、user_prompt、generation_options、json_mode 完全一致，只改模型名**。未向 Decision/Judge 提供 label、expected_action、necessary_questions 或 adjudication。
- 预设累计上限 Decision 7、Judge 19；实际 **Decision 6、Judge 14，共 20 次请求**。修正参数后重发的不同请求也计入同一台账。缓存重放不再次发送。
- 18 份返回了 usage 的响应合计 **49,353 tokens**：输入 37,780，输出 11,573，其中已报告的思考 token 为 10,056。该统计含两次 length 截断；400 参数拒绝和一次超时没有 usage，不能据此断言它们零消耗。费用未查账，不估算。
- 所有原始请求/响应及失败尝试保留。没有业务工单写入、回复发布或人工审核；本轮不是完整 HTTP/数据库端到端复测。
- 冻结 M4 目录执行前后哈希一致，原结果、label、adjudication 未修改。本轮是已知失败样本诊断，不是独立盲测或稳定性测试。

## 3. 一次真实修正

| 样本 | GLM-5.3 修正结果 | 第二次 Judge / 系统结果 |
| --- | --- | --- |
| 016 | 输出达到 4096 上限，4094 个为思考 token，最终内容仅为 JSON 开头 | 未形成可验证提案，guardrail_repair_failed；没有第二次 Judge |
| 034 | 删除“届时会由人工确认”，说明恢复需要人工核实并获授权，再决定后续处理 | Judge 将流程/权限前提再判为承诺，semantic_guardrail_failure；复核认为仍有过度拦截 |
| 036 | 删除“人工审核后会确认”，改为“需要人工审核后再决定如何答复” | **PASS**；本轮完成“拒绝 → 修正一次 → 放行”，上一轮此例修正后仍被误拒绝 |

034 的争议原文为“此类恢复与覆盖操作需要人工核实记录丢失范围和可用恢复来源，并在获得授权后由人工执行”。结合回复前后的“建议”“需要审核后再决定”，它在说明执行者和权限前提，没有声称已经安排某个人必将执行。该复核由报告作者依据任务语义完成，非独立人类标注。

## 4. 追问完整性：本轮未能验证

**005：** 首次请求因思考参数不兼容被服务端 400 拒绝；修正参数后，请求在 30 秒上限内超时。失败请求未再发送，没有可评估的新 Decision 文本。

**026：** 仅发送一次有效参数请求，允许最多 90 秒诊断等待；约 56.9 秒后返回 `finish_reason=length`。4096 个输出 token 中 4094 个为思考 token，最终 JSON 只返回开头，未进入 Judge。

因此不能从本轮得出 GLM-5.3 的追问是否完整，也不能沿用旧模型的完整性结论冒充新模型实测。原有完整性缺陷仍是未完成的验收项；Semantic Judge 的四类职责没有扩充。

## 5. 参数兼容性与代码修正

最初沿用旧 `enable_thinking=False`，服务端实际返回 `invalid_parameter_error`：该参数只允许 True。官方文档也说明 GLM-5.3 仅支持思考模式。[阿里云 GLM 文档](https://help.aliyun.com/en/model-studio/glm)

已新增按模型选择 Decision 生成参数：GLM-5.3 使用 `enable_thinking=True`、`max_tokens=4096`，保留供应商默认 reasoning effort；旧模型保持原有参数。相应真实调用和开发缓存指纹均使用同一参数函数。44 项离线测试通过。提示词、Judge 规则和 schema 未修改。

这属于必要的调用兼容修正，**不是完全同参数的 Decision 模型对比**。第一次 400 失败保留并计入额度；之后同输入使用改变后的参数发起一次调用，超时后不再重发。生产 `AgentRunner` 仍使用原有每阶段至多 30 秒和总超时预算；未为了诊断放宽生产超时。

尚未发送的后续 Decision 使用 90 秒诊断等待，修正路径总诊断预算 120 秒；这些区别已记录在台账与报告。扩大等待并未解决 026/016 的输出截断；不能将本轮诊断通过的部分样本当成整套生产兼容性验收完成。
