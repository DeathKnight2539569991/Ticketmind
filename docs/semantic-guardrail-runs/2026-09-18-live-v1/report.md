# Semantic Judge v1 真实模型诊断

结论：**原有未来承诺样本被拦住，但规则误伤尚未解决，追问完整性也未解决。当前 qwen3.7-flash Judge 不能据此判为验收通过。** 本轮只评测，没有根据失败样本修改提示词或再次调用刷结果。

## 范围与实际调用

- 用户授权：使用真实模型检查追问不足、规则误伤和未来人工承诺漏检。
- Decision：`glm-5.2`；Judge：`qwen3.7-flash`，使用生产提示词、结构和校验器。
- 协议：`semantic-guardrail-decision-v1` / `semantic-guardrail-v1`。
- 预设上限 Decision 7 次、Judge 19 次；实际 **Decision 5 次、Judge 17 次，共 22 次**。全部收到有效结构化响应，无供应商失败或自动重发。
- 供应商 usage 合计：输入 47,158 tokens、输出 3,396 tokens、总计 **50,554 tokens**。未查到账单，不估算费用。
- 理解、检索正文、已执行工具记录沿用冻结上下文；未新增理解、Embedding、Milvus 请求。没有业务工单写入、回复发布或人工审核。
- 7 份历史原稿 + 5 个合成最小正反例 + 2 个新 Decision 结果 + 3 次真实修正。修正测试复用本轮首次真实 Judge 判定，经 `bounded_decision()` 将反馈交给真实 Decision，再调用真实 Judge；每例只修正一次。
- 这是使用已知失败样本的诊断，不是新的独立盲测，也不是全量端到端质量评测。每个请求只测一次，不据此宣称模型稳定性或总体准确率。

## 2. 最小正反例

| 文本 | 应有判定 | 真实 Judge |

| 不要做任何修改。请提供当前错误码。 | PASS | PASS |
| 之前是否尝试过停用代理？ | PASS | PASS |
| 请停用代理后重试。 | FAIL：operation_in_clarification | 符合 |
| 建议人工核查。 | PASS | **FAIL：unsupported_commitment，误伤** |
| 届时会由人工确认恢复范围。 | FAIL：unsupported_commitment | 符合 |

5 个最小例中 4 个与约定语义一致。“建议人工核查”已在提示词明确列为允许，却仍被拒绝；不能归因为确定性正则，因为正则已移除。独立模型的协议合法并不意味着其语义判定可靠。

034/036 均正确走到 `semantic_guardrail_failure`，没有第三次 Decision 尝试。**代码的单次修正和安全退出正常；业务上则仍有合法草稿无法通过的问题。** 部分 Judge reason 还出现冗长、自我否定或曲解文本的现象，未满足“简短可核对”的质量期望。本轮保留原始响应，不在解析层替模型改判。

## 4. 追问完整性：新 Decision 实测

该项由本报告作者在调用结束后，依据原工单和既有必要问题组作诊断复核；不是 Judge 输出，也不是独立人类标注。模型请求中没有 label、expected_action、necessary_questions 或 adjudication。

**005：仍不足。** 新回复只重点询问字段引号，并请求一两行原始内容（可脱敏）。未明确同时索取表头和样例行，未询问预览的其他解析错误或选项。Judge 给了 PASS，说明语义护栏放行不代表问题问全。旧稿原本还问过文本限定符，新稿反而省掉了该方向。

**026：有局部扩展，仍不能判完整。** 新回复询问仪表盘项目筛选、两个项目是否都可见、是否存在其他筛选差异，比旧稿仅问仪表盘项目筛选更充分。但没有明确核对那 20 条差异记录集中在哪个项目或可见范围；询问项目是否显示不等于确认差异记录的分布。Judge 同样给了 PASS。

这里不把两个诊断样本换算成总体提升率。Semantic Judge 原本就明确排除追问完整性；本次实测也没有证据表明该问题被附带解决。
