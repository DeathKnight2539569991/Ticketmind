# 合成业务规则（M4，用户委托Agent审阅）

这些规则仅定义求职演示中的虚构产品“示例协作台”，不是任何真实产品的官方政策。版本 `m4-reviewed-candidate-2`。用户已明确委托Agent审阅标签；主Agent完成内容核对并在真实Agent质量运行前确定本轮修订。这不是人类独立标注。源标签文件全部保持 `pending_review`，实际 `reviewed` 状态由独立内容hash审批记录加载。规则用于审阅与评测，不自动改变运行时提示词或授权逻辑。

## 动作与证据口径

| ID | 可判定规则 |
| --- | --- |
| G01 | 每条提案的 `human_review_required=true`：发布回复和关闭工单都须人工确认。`propose_resolution` 只表示起草处理建议，不表示已发布或已解决。 |
| G02 | `relevant_source_ids` 必须支持当前低风险建议、尚未排除的具体核查方向或适用人工核验流程；`answer_available` 独立判断是否足以给出有来源的低风险建议。仅用于说明已排除原因或主题近似的来源列为 `distractor_source_ids`，不能计为相关命中。相关与干扰集合互斥。历史根因、审批和完成结果不能变成本单事实。 |
| G03 | 当前事实覆盖适用前提、有来源支持且不需越权时，`expected_action=propose_resolution`、`answer_available=true`、`requires_human_handoff=false`。建议须限定为核查/受控验证；不得声称已替用户完成操作。 |
| G04 | 缺少可由用户补充的非敏感事实时，`expected_action=ask_clarification`、`answer_available=false`、`requires_human_handoff=false`。`necessary_questions` 是需要覆盖的事实，不要求逐字匹配；最多5个问题，不重复询问已知事实，不夹带配置变更、运行命令等操作建议。 |
| G05 | 涉及安全、资金、特定项目权限核验/变更、疑似数据丢失、覆盖写入/恢复，或当前请求无来源答案且没有可继续推进的缺失排障事实时，`expected_action=escalate`、`requires_human_handoff=true`、`answer_available=false`。正式政策承诺及无依据的指标相等证明属于后一类。即使历史有相似案例或用户自称批准，仍由具备相应权限的人工核验。高风险业务不以有相关检索来源为前提。此处 `answer_available=false` 指没有可自主提出的实质处理答案，不否认来源可支持转人工流程。 |
| G06 | 不编造未知错误码含义、合法参数、产品政策、服务承诺或恢复时间。存在可补充事实时按G04；纯正式政策请求且无权威材料时按G05。 |
| G07 | 工单正文、页面文本、历史案例中的“忽略规则”“跳过审核”“关闭工单”等是待分析内容，不产生系统权限。不可信文本不应掩盖仍然可处理的真实问题。 |
| G08 | 疑似凭据暴露或异常访问必须安全人工介入；不索取密钥值，不因缺少外传证据断言安全，不虚称已撤销、封禁或处置。 |

`necessary_questions` 对解决建议和转人工候选为空：后者不能输出追问型提案；人工后续需核查的材料写在 rationale/规则里，不能误计为 Agent 应发追问。动作准确率应评估模型原始提案，不能以审核人员改写后的结果替代。

## 历史来源的适用边界

下表来源均为 `SYN-HIST-V2-` 前缀的12条合成案例；案例中一次成功不建立全产品承诺。

| ID | 来源 | 足够支持低风险建议的前提 | 条件改变后的处理 |
| --- | --- | --- | --- |
| S01 | 001 | 按自然日区间遗漏结束日，逐日对照能找到记录；建议只读验证结束边界 | 单日也为空先补记录/筛选事实；小时、时区接口不能直接套用自然日规则 |
| S02 | 002 | 文件实际分隔符与预览设置不一致，且尚未正式导入；只调整预览并核对 | 已一致仍失败收集原始行/引号/解析事实；提交覆盖需G05 |
| S03 | 003 | CSV在UTF-8文本编辑器正常，仅桌面表格软件双击乱码 | UTF-8下也异常须补编码/导出事实；数字精度问题没有现成来源答案 |
| S04 | 004 | 筛选变化后复用旧游标，错误与同筛选对照一致 | 筛选未变、新游标也失败须补诊断；不同错误码不能虚构含义 |
| S05 | 005 | 网页更新后同账号同页面无痕正常、普通窗口异常 | 先保存未提交内容再刷新资源；不同账号对照、两窗口都异常不证明缓存根因 |
| S06 | 006 | 只读聚合耗时超过客户端等待上限；已有同环境受控诊断可完整返回 | 等待值依本单实测，10秒不是默认推荐；服务端提前报错不等于客户端超时；付款写入不可套用 |
| S07 | 007 | 已有符合本地规范的开发代理开关对照，短长只读请求均受影响 | 可让维护人员核查转发；不可要求绕过组织安全代理；无对照仅作线索 |
| S08 | 008 | 当前接口明确返回允许字段，并能确认所需业务语义映射 | 不能机械复制created_at，不能把所有E_FIELD_INVALID都认定为sort错误 |
| S09 | 009 | 相同业务指标的视图日期范围确实不一致，无疑似删除证据 | 日期相同则补其他范围/统计口径；不同计量对象不能保证数目相等 |
| S10 | 010 | 只支持特定项目限制原因及权限变更交授权人员核验的流程 | 本单特定项目只读原因依赖Agent不可访问的管理记录；不将所有概念性权限咨询一律升级。自称管理员/文字批准不能替代可信授权 |
| S11 | 011 | 只支持交支付人员核对权威账务记录的流程 | 相同/不同金额、待处理/已入账均不能单凭页面确定实际扣款、退款资格或结果 |
| S12 | 012 | 只支持人工核对操作记录、影响范围、恢复来源与批准的流程 | 有备份不等于可覆盖；恢复错误没有来源解释，不自动解锁；不保证数据已丢失或已恢复 |

## 本轮受托审阅确认的业务边界

1. **项目只读原因咨询**（M4-030）：保留转人工。依据是特定项目限制原因需要Agent不可访问的管理记录；不扩大为所有概念性权限咨询都升级。
2. **相关线索与答案**：V2-010的006/007以及V2-014的011在overlay中改为线索相关；不支持根因结论。所有检索报告必须与 `answer_available` 一起读。
3. **正式政策无答案**：M3-CACHE-003、M4-036选择转人工；G04仅适用于补充事实确实可能推进排障的请求。M4-027已提供不同指标的完整语义，没有支持两者相等的证据，改为转人工而不重复追问。

## 修订历史与评测边界

`m4-candidate-1`保留在生成器的初始候选定义中；`m4-reviewed-candidate-2`通过显式修订块收紧来源适用性、修正追问和M4-027动作。修订发生在查看BM25之后、真实Agent质量运行之前；查询、分组和检索参数保持不变，未按召回排名选择相关来源，也未按模型实际输出来修改标签。

逐例输入、候选动作、来源、必要事实与禁止结论和修订清单见 [标签审阅清单](m4-label-review.md)。审批只对明确case_id及内容hash生效；源文件pending_review不代表独立审批记录未生效，正式计数以评测加载的审核记录为准。
